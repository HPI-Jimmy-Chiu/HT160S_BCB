CodeGraph 與 Superpowers — 白話評估 + 操作說明書

對象：HT160S_BCB 專案（BCB6 / C++Builder 6 工控程式，單人開發、重度使用 Claude Code、大量從 HT172 移植）。日期：2026-06-29。
原始 Markdown：docs/tools/codegraph-superpowers-evaluation.md
一句話結論：CodeGraph 值得馬上試（低風險、對大型舊碼很有用，重點用「影響分析」）；Superpowers 借觀念、只挑幾個技能裝，不要整套照搬——TDD 與 git-worktree 不適合本專案。

0. 懶人包

工具它是什麼（白話）效益風險建議
CodeGraph 把整個程式碼先建成一張「索引地圖」放在本機，AI 不用一個一個檔翻，一次查詢就知道「誰呼叫誰、改這裡會炸到哪」 ★★★★★ 低 先試，重點用 impact 影響分析

1. CodeGraph 是什麼？

GitHub：colbymchenry/codegraph（MIT 授權，TypeScript）。

問題情境：現在 Claude 理解程式靠「一直開檔、一直 grep、一路追路徑」。在 HT160S 這種有 main.cpp、csystem.cpp、aLoader.cpp、aColor.cpp、一堆 form 與全域變數的大專案，既花時間又花 token（= 花錢）。

CodeGraph 的做法：先用 tree-sitter 解析整個專案，把「函式、類別、誰呼叫誰、誰 include 誰」存進本機 SQLite（.codegraph/codegraph.db）。之後 AI 查這張地圖，一兩次就拿到答案，不用翻檔。它以 MCP server 形式接進 Claude Code。

對本專案最關鍵的三件事

  1. 影響分析（impact / blast radius）——這是 grep 做不到的。改函式前先問「誰呼叫它？會影響哪？」。你最痛的就是改 A 壞 B 的回歸（hang up、silent stop、互鎖），這功能正中要害。
  2. 100% 本機、不外傳——全程在你電腦上跑，無資料上雲。對公司專屬工控原始碼很重要。
  3. 支援 C++ 與 Pascal/Delphi——涵蓋 .cpp/.h；BCB6 的 .dfm 屬 Pascal 系，部分也能吃。

官方/文章宣稱：tool call 大幅減少、速度更快、檔案讀取趨近於零（README 約「少 58% tool call、快 22%」，其他文章宣稱更高）。實際因專案而異，但方向正確：更省、更快、更準。

⚠ 給本專案的誠實提醒
  • BCB6 解析品質要先驗：tree-sitter 的 C++ 文法針對標準 C++，BCB6 有 __published、__fastcall、AnsiString、VCL 巨集等非標準語法。函式/類別大多能解析，但可能有漏。裝完先跑 codegraph status 看符號數再決定信任程度。
  • 只在 D:\HT160S_BCB 跑 init，不要去 D:\HT172（唯讀參考，無需建索引）。
  • .codegraph/ 要加進 .gitignore。
  • 它提供的是唯讀程式碼情報，不碰機台控制，安全。

2. Superpowers 是什麼？

GitHub：obra/superpowers（作者 Jesse Vincent / Prime Radiant；Claude Code 官方 marketplace 也收錄）。

它不是工具，是一套「工作習慣」外掛。安裝後塞進一堆「技能（skill）」，引導 Claude 不要一上來就寫扣，而照專業流程走：腦力激盪釐清需求 → 寫計畫 → 照計畫做 → 做完驗證。

分類技能白話
協作brainstorming動手前先問清楚、探索替代做法、產出設計文件
協作writing-plans / executing-plans把工作切成 2–5 分鐘小塊、寫成計畫再照做
除錯systematic-debugging4 階段找根因，不靠猜
驗證verification-before-completion做完一定要拿證據驗證才算完成
測試test-driven-development強制 RED→GREEN→REFACTOR（先寫失敗測試再寫扣）
協作requesting/receiving-code-review任務間自動 code review，嚴重問題擋下不准過
並行dispatching-parallel-agents / subagent-driven-development派多個子代理平行做、兩段式審查
並行using-git-worktrees / finishing-a-development-branch用 git worktree 隔離平行工作、收尾合併
後設writing-skills教 AI 怎麼寫新的 skill
⚠ 給本專案的誠實提醒（重要）
你已經自建一套很完整的治理系統（.github/instructions、十幾個 domain skill、agents、hooks、70+ memory）。Superpowers 是「通用版」，整套照搬會跟你的硬規則打架：
  • ✗ test-driven-development 不適合——BCB6 工控程式沒有單元測試框架，驗證靠「上機台跑」。這 skill 會強迫「沒測試就刪扣重來」，直接衝突你的 build-gate + 上機驗證流程。務必忽略/關掉。
  • ✗ using-git-worktrees / 平行子代理 風險高——BCB6 單機編譯、有 .obj 產物、還有「designer 存檔會吃掉元件」陷阱。多 worktree 平行改 .dfm/.h 很危險。維持「一次一條線」較安全。
  • 跟既有 skill 重疊——你已有 /code-review、docs/plan/ 計畫流程、State Record 除錯慣例。Superpowers 對應技能是補強而非取代。
結論：把它當成一份高品質的觀念清單，而非「裝了就照單全收」。真正值得吸收的是 4 個：brainstorming、writing-plans、systematic-debugging、verification-before-completion——而且可以直接寫進你自己的 .github/skills，不一定要裝整套外掛。

4. 白話操作說明書

4-A. CodeGraph 安裝與使用（Windows）

步驟 1：裝 CLI（PowerShell，任選一種）

# 方法 A：官方安裝腳本
irm https://raw.githubusercontent.com/colbymchenry/codegraph/main/install.ps1 | iex

# 方法 B：用 npm（若已有 Node）
npm i -g @colbymchenry/codegraph

CLI / MCP server 自帶 runtime，本身不需先裝 Node（只有方法 B 的 npm 才需要）。

步驟 2：把 MCP 接進 Claude Code

codegraph install

會自動偵測 Claude Code、寫入 MCP 設定並加上使用指引。

步驟 3：在本專案建索引（一定要在對的資料夾）

cd D:\HT160S_BCB
codegraph init
codegraph status      # 看抓到多少符號 -> 判斷 BCB6 解析品質

步驟 4：加進 .gitignore

.codegraph/

常用指令速查

指令用途
codegraph explore <問題>拿到相關符號＋呼叫流程＋片段
codegraph query <名稱>用名字搜尋符號
codegraph impact <符號>⭐ 影響分析：誰呼叫、改了影響哪
codegraph affected [檔案]找受影響的測試/檔案
codegraph status看索引統計
codegraph sync手動增量更新（平常會自動偵測檔案變更同步）
codegraph upgrade原地升級

裝完怎麼用：你不用每次下指令，Claude（透過 MCP）會自己查這張地圖。你只要正常描述任務即可——我會優先用它做影響分析再動手。

4-B. Superpowers 安裝與使用

步驟 1：在 Claude Code 裡裝外掛

/plugin install superpowers@claude-plugins-official

或用作者的 marketplace：

/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace

步驟 2：（重要）先決定要不要全開

  • ✓ 想用 → 直接描述任務，讓 brainstorming / writing-plans / systematic-debugging / verification-before-completion 自然介入。
  • ✗ 不想被 TDD 綁架 → 明確告訴我「這專案不做 TDD、不用 worktree、照 HT160S build-gate 驗證」，或乾脆不裝外掛，改把這幾個觀念寫進你自己的 .github/skills。
最適合你的替代方案：不裝外掛，請我把 Superpowers 的 systematic-debugging、brainstorming、writing-plans 三個流程，改寫成符合 HT160S 規則的版本放進 .github/skills/。好處：保留觀念精華、完全相容你的 Big5 / build-gate / 上機驗證 / write-boundary。

5. 給本專案的最終建議

  1. CodeGraph：先 pilot 一週。裝好跑 codegraph status 驗 BCB6 解析品質；若符號夠多，就把「改碼前先 impact」變成習慣。風險低、可隨時移除。
  2. Superpowers：不要整套裝。真正價值是 4 個觀念（brainstorm / plan / 系統化除錯 / 完成前驗證）。最佳做法是把它們內化進你自己的 .github/skills，而非引入會推 TDD/worktree、跟硬規則衝突的通用外掛。
  3. 兩者都不碰機台控制、都可逆——CodeGraph 是唯讀情報、Superpowers 是流程引導。可放心試，不滿意就移除。
