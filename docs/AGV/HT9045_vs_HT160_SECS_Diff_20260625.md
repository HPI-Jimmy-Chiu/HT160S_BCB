# HT9045 vs HT160 SECS 命令面差異報告（KYEC AMR 導入用）

> **動機 / 範圍**
> HT160 與 HT9045（HT-9046LS）服務**同一客戶 KYEC 京元電子**、提供**相同的 AMR/AGV 自動搬料功能**；HT9045 已在客戶端量產部署。本報告逐一比對兩者在**完整 SECS 命令面**的差異，列出 HT160 為了重現 HT9045 KYEC AMR 行為**必須補齊的具體缺口**。
>
> 比對維度共 4 個：
> 1. **RCMD**（S2F41 Remote Command）
> 2. **CEID / 事件與 report 架構**（S6F11 + S2F33/35/37）
> 3. **AMR 四站交握機制**（Loader / Empty / Color / Auto）
> 4. **S/F 訊息 + SVID / ECID**（連線、Alarm、EC、S125 等全訊息面）
>
> **來源**
> - HT9045 權威細節：`D:\HT160S_BCB\docs\AGV\KYEC_AMR_SECS_Handshake_HT9045_20260625.md`（由 HT9046LS codebase `V3.32.810` + KYEC 2026-06-08 真實連線 log 整合校對）。
> - HT160 現況：本 repo SecsGem 原始碼，主要為
>   `HT160S_Program_BCB_V1.0.0.0\SecsGem\uHGemHT160.cpp`（HT160Gem 子類，RCMD/SV/EC/CEID 註冊）、
>   `uHGemClass.cpp`（HTGem 基底 dispatch + stubs）、
>   `uHGemEquipment.cpp`（S6F11 序列化、IsEnableEvent、SaveEventReportData）、
>   `uAgvStation.cpp` / `uAgvStation.h`（TAgvCoordinator 9 站交握引擎）、
>   `UsecegemMainFrom.cpp`（事件入口 / DataID 約定）。
>
> **方法說明**：本報告所有「HT160 現況」均以上述原始碼之 `file:line` 為據；「HT9045」均引自參考規格之 `file:line` 或 log。凡標註「相同」者為**機制與線上數值皆同**；凡因命名相同但語意/行為不同者，一律歸入「行為不同」並於影響欄說明。**未在來源中出現的 HT160 行為，本報告不臆測。**

## 總覽差異摘要表

| 維度 | 兩邊相同 | 僅 HT9045 有（HT160 缺） | 僅 HT160 有 | 行為不同 | 單一最大缺口 |

## 一、RCMD（S2F41 Remote Command）

HT160 僅實作 **6 個 RCMD**：`SET_LOT_INFO`、`PAUSE`、`ONLINE_REMOTE`/`ONLINE`、`ONLINE_LOCAL`、`LOTSTART`、`START_AGV`（`uHGemHT160.cpp:652-868`）。HT9045 約 **30 個**。兩者皆用同一套 `UpperCase()` + `AnsiPos(...)==1` 前綴鏈，單一分派點為 `HT160Gem::S2F42_Host_Command_Acknowledge()`（`uHGemHT160.cpp:618`，由 `UsecegemMainFrom.cpp:124` 路由）。

### 1.1 兩邊相同

| 項目 | 說明 |
|------|------|
| `LOTSTART` | 兩邊皆有（HT9045 `uHGemHT9045.cpp:2081` / HT160 `uHGemHT160.cpp:737`），皆登記 lot 意圖。**但行為差異大**（見 1.4）。 |
| `PAUSE` | 兩邊皆可讓 host 遠端停/暫停運轉機台（HT9045 `uHGemHT9045.cpp:1081` PAUSE/STOP 共線 / HT160 `uHGemHT160.cpp:710`）。HT160 落 `SystemStart=false`+`SoftStop=true`。 |
| `ONLINE_LOCAL` | 兩邊皆接受控制狀態命令（HT9045 `uHGemHT9045.cpp:1527` / HT160 `uHGemHT160.cpp:729`）。HT160 為 mirror-only（`iControlState=4`）。 |
| `ONLINE_REMOTE` | 兩邊皆有（HT9045 `uHGemHT9045.cpp:1532` / HT160 `uHGemHT160.cpp:721`）。HT160 為 mirror-only（`iControlState=5`）。 |
| `START_AGV` | 兩邊皆為 AMR 派車 RCMD（HT9045 `uHGemHT9045.cpp:1655` / HT160 `uHGemHT160.cpp:801`），皆解析內層 `{cpName,cpValue}` 對並對 `LoaderTrayCount` 特別處理。**行為落差大**（見 1.4）。 |

| 項目 | 說明 |

|------|--------|-------|------|

## 二、CEID / 事件與 report 架構

HT160 事件採 **enum `SECS_EVENT`**（`uHGemHT160.h:7-44`）：operator 事件 1-31 + AGV 272-275。報表為**靜態**，於 `AddReprot()`（`uHGemHT160.cpp:264-301`）一次建立、`AddCEID()`（`:236-262`）固定 CEID→report 連結。HT9045 為**全 host-dynamic**（S2F33/35/37 每次連線重建）。

### 2.1 兩邊相同

| 項目 | 說明 |
|------|------|
| 四個 AMR CEID 號碼與角色 | 272 AGVSupplement（要料）、273 AGVLDUnLDStatus（交握中）、274 AGVLDUnLDFinish（完成）、275 AGVLdID（carrier/tray id）皆相同。 |
| 「哪個站」用 P-bit 字串 | P1=Loader, P2=Empty, P3=Color, P4..=Auto；每事件恰一個 bit set（單站規則）。 |
| AGV SVID 號段 | 38219=Supplement bitmap、38220=LD/UnLD Status bitmap、38221=LD/UnLD Finish bitmap；carrier-id SVID 自 38202 起。 |
| S6F11 外層 envelope | `L[3]{U4 DATAID, U4 CEID, L[reports]{L[2]{U4 RPTID, L[n]{values}}}}`，期待 S6F12 ack。 |
| 272-275 為 equipment-initiated | handler 觸發 EventReport、host ack；兩邊皆非 host command。 |
| Report1 status SVID 低段對齊 | 1001 Model、1003 SW Version、1021 UPH、1027 System Time，兩邊皆同。 |

### 2.2 僅 HT9045 有（HT160 缺）

| 項目 | 說明 |
|------|------|
| **S2F33 Define-Report** | HT9045 host 連線時動態定義 RPTID→SVID（KYEC log 502/513/503/504/2000/2001）；persistent def 僅存 Report1→SVID1027。**HT160 無 case 33**（`uHGemClass.cpp:82-92` 的 S=2 switch 僅 17/25/31/41/13/15）→落 S9F3；`S2F34_DefineReportAcknowledge` 為 SendUnsupported stub（`uHGemClass.cpp:165`）。HT160 報表硬編於 `AddReprot()`。 |
| **S2F35 Link-Event-Report** | HT9045 host 連線 link CEID→RPTID set（log_13 共 35 link 區塊，例 272→502+2000+2001）。**HT160 無 case 35**→S9F3；`S2F36` 為 stub（`uHGemClass.cpp:166`）。CEID→report 固定於 `AddCEID()`。 |
| **S2F37 Enable/Disable-Event** | HT9045 連線開場 `Disable all` 後 enable 選定 CEID；CEID 被 disable 時 fired 會印 `CEID=N be disabled , abort send` 並抑制。**HT160 無 case 37**→S9F3；`S2F38` 為 stub（`uHGemClass.cpp:167`）。更糟：`THGem::IsEnableEvent()` 硬回 true（`uHGemEquipment.cpp:353-356`），**無 per-event enable bit**。 |
| **RPTID 502 批次上下文 report** | HT9045 502 = SVID `1006 1007 1011 3 1501 1517 1518 1513`，幾乎掛在每個 CEID（含 272-275）。payload 為 L[8]：LotID/Job、carrier kind('AGV')、製程狀態('RT1 ART'/'Alarm'/'Cleaning')、timestamp、recipe 檔名、I4 I4 I4。**HT160 無對應上下文 report**——272-275 只帶 bitmap/carrier-id（report 2/3/4/5），**零 lot/job/timestamp/recipe**。 |
| **RPTID 2001 計數陣列（15 SVID）** | HT9045 2001 = SVID 38222..38236（15 筆），link 至 CEID 272。**HT160 無計數陣列 report**；272 只帶單一 bitmap SV。（HT160 雖在 `AgvStation` 表保留 38222-38245 給 TrayCount/DeviceCount，但未組成 15-element 2001。） |
| CEID 35/36/37 Auto1/2/3 Full | HT9045 `asendic_Auto.cpp:1098` case 1100 實體 full sensor trip 時觸發（與 unload-complete 為**不同事件**）。HT160 enum（`uHGemHT160.h:7-44`）**無 Auto-Full CEID**；Auto full 在 HT160 透過 272 demand 浮現。 |
| CEID 136/137/138 Auto1/2/3 Unloading-tray | HT9045 `asendic_Auto.cpp:1769` case 1500 unload 後觸發；真實 log 帶空 report body。HT160 **無 per-Auto-station unload CEID**；對應的是泛用 274（帶 P-bitmap）。 |
| 兩段式 Auto unload 交握 | HT9045 spec 3.4：handler 報 136-138/35-37 → host 決策 → host 下 `START_AGV(AUTOn/Action)` → 273/274。此 round-trip 與 START_AGV RCMD 在 HT160 不存在（`S2F42_Host_Command_Acknowledge` 為 stub，`uHGemClass.cpp:169-173`）。HT160 AGV 由 `TAgvCoordinator` 1s tick 內部驅動。 |
| host-pull Loader 供盤（LoaderTrayCount/iSECSSetTrayCount） | HT9045 Loader 為 host-pull：host 送 `START_AGV(Loader/Action, LoaderTrayCount='1', LoaderICCount='3')`；handler 存 `iSECSSetTrayCount=atoi`（`uHGemHT9045.cpp:1681-1684`），total=`iSECSSetTrayCount + iAMRCoverTray`（`uLotInfo.cpp:13056`）。HT160 無 host-供盤數 ingestion；tray count 存 `AgvStation[].TrayCount` snapshot，非 host 收。 |

### 2.3 僅 HT160 有

| 項目 | 說明 |

## 五、HT160 導入 KYEC AMR 的補齊缺口清單（P0/P1/P2）

> 優先序：**P0 = 不補則 KYEC host 連線/啟動即失敗**；**P1 = 影響 AMR 功能對等或客戶可能依賴**；**P2 = 功能/便利性，視 KYEC 規格決定**。
> 機制提醒（全清單通用）：RCMD 移植在單一分派點 `HT160Gem::S2F42_Host_Command_Acknowledge()`（`uHGemHT160.cpp:618`）加 `AnsiPos(...)==1` 前綴分支即可，但**務必維持 longer-before-shorter 排序**並保持 no-FSM procedural 風格。Report 分派在 `HTGem::Dispatch()` case 2 switch（`uHGemClass.cpp:82-92`）加 case。

### P0 — 阻斷級

**P0-1　Host-dynamic report 支援（S2F33/S2F35/S2F37）**
- 缺口：HT160 無 S2F33 Define-Report / S2F35 Link-Event-Report / S2F37 Enable/Disable-Event handler。
- 為何重要：KYEC host 連線**必走** disable→define→link→enable 序列；缺則三者皆 S9F3，host 永遠建不起 collection event，整條 link 形同不可用。
- HT160 現況：case 33/35/37 不在 `uHGemClass.cpp:82-92` 的 S=2 switch→落 S9F3；S2F34/36/38 為 SendUnsupported stub（`uHGemClass.cpp:165-167`）；`IsEnableEvent()` 硬回 true（`uHGemEquipment.cpp:353-356`）；`SaveEventReportData()` 為 no-op（`uHGemEquipment.cpp:302-305`）。
- 建議動作：(a) 在 S=2 switch 加 33/35/37 case；(b) 把 S2F34/36/38 stub 換成真 ACK 並 mutate runtime 表；(c) 以可變 RPTID→SVID 與 CEID→RPTID-set 表取代不可變 `AddReprot`/`AddCEID`；(d) 加 per-CEID enable bit 讓 `IsEnableEvent()` 查詢，並補 `CEID=N be disabled, abort send` 抑制路徑；(e) 讓 `SaveEventReportData()` 真正持久化（至少 Report1→SVID1027 如 HT9045 .def）。**替代方案**：維持 HT160 static，但要求 KYEC host 端 config 跳過 dynamic 定義並接受固定報表（屬 host-side 讓步、非 code 對齊）。

**P0-2　連線握手 functional 化（S1F13/F14 + S1F17/F18 + S1F1/F2）**
- 缺口：標準 GEM establish-comm 與 request-online 握手在 HT160 為 stub/未 dispatch。
- 為何重要：host 無法完成標準上線握手；HT160 達 online 僅靠 ONLINE_* RCMD 設 int 鏡像。
- HT160 現況：S1F13/S1F14 為 base SendUnsupported（HT160Gem 未 override，`uHGemClass.cpp:79,150-152`）；S1F17 無 case→S9F3、S1F18 為 stub（`:154`）；S1F1/S1F2 未 override→stub（`:76,147`，但 sibling S1F4/S1F12 已 override）。
- 建議動作：在 HT160Gem override S1F13/S1F14 回真實 model('HT-160S')/version CommAck；在 S=1 switch 加 case 17 並實作 S1F17/S1F18；實作 S1F1→S1F2 OnLine Data。

### P1 — AMR 功能對等級

**P1-1　生產 START RCMD + autostart chain**
- 缺口：HT160 無遠端生產啟動動詞（最關鍵 RCMD 缺口）。
- 為何重要：host 可遠端 PAUSE 但**無法遠端 start**；HT9045 的「START_AGV 鋪 ActionFlag → START 消費」兩段啟動無法重現。
- HT160 現況：S2F42 無 START/REMOTE_START（`uHGemHT160.cpp:618-868`）；machine start 為 operator-only（`main.cpp:1662`）；START_AGV 只 flag prep+lock，無人遠端消費。
- 建議動作：移植 HT9045 `START`@1748（與 `REMOTE_START`@1725），含 `bUseSECSGEMAutoStart`/AMR `bLotStart`→`bSameSetupFileNoDownload`+`bAMRReceiveStart`+`CheckActionFlag()` 鏈；須發明 HT160 ActionFlag/CheckActionFlag 等價物，並把 BeginPrep→loader/unloader task kick-off 接起；保留 idle/`HasICUnderMachine` guard。

**P1-2　START_AGV 參數語意：驅動實際任務**
- 缺口：HT9045 START_AGV kick 起 Initial Loader/UnLoaderTask 並設 iSECSSetTrayCount；HT160 只設 `AgvCoord.TrayCount[0]` + BeginPrep lock，無 motion。
- 為何重要：功能對等的核心。
- HT160 現況：`uHGemHT160.cpp:801` + `uAgvStation.cpp:298`，BeginPrep 設 Handshake=AGV_PREP+lock，無 task。
- 建議動作：決定 BeginPrep 是否額外啟動 task（或靠 P1-1 的 ported START 驅動）。**保留 HT160 已涵蓋的 AUTO4-6**（HT9045 靜默丟棄 AUTO4/5）。`LoaderICCount` 兩邊皆忽略；若 KYEC 需要，加 consumer。

**P1-3　Empty/Color 傳輸模型對齊（先決策！）**
- 缺口：HT9045 KYEC 把 Empty/Color 跑成純機構 sensor+TrayArm（零 SECS，159-165 死碼）；HT160 對 P2/P3 發 272/273/274。兩者**直接矛盾**。
- 為何重要：HT9045 spec 六.4 明列此為「最易誤解」點；若客戶期待靜音機構補盤，HT160 會發出非預期 272/273/274。
- HT160 現況：`InfeedShortage`/`InfeedReady`/`InfeedFinished` 對 P2/P3 走完整 SECS 握手（`uAgvStation.cpp` PollAndCall/ServiceHandshake）。
- 建議動作：**先向 KYEC 確認意圖**。(a) 若 KYEC 確實要 Empty/Color 走 AMR→HT160 正確且**領先** HT9045，保留；(b) 若 KYEC 期待純機構→gate 掉 HT160 P2/P3 的 SECS emission（infeed loop）以對齊 HT9045。

**P1-4　Auto 兩段式預通知事件（35-37 Full + 136-138 Unloadtray）**
- 缺口：HT9045 host 依 discrete CEID 35-37/136-138 決定派車（**先於** START_AGV）；HT160 無、直接 fire 272。
- 為何重要：若 KYEC host 狀態機等 35-37/136-138 才派車，HT160 不發則 host 拿不到預期訊號。
- HT160 現況：enum 僅 1-31 + 272-275（`uHGemHT160.h:7-44`），Auto full/unload 由 272 浮現。
- 建議動作：在 HT160 Auto full/unload 路徑加這些 equipment-initiated S6F11 emit，再保留 272 作實際 call，以還原兩段式觸發。**用 HT160 array-index 風格（si=a+3），勿照抄 HT9045 `+Pos`。**

**P1-5　Alarm 回報（S5F1 + S5F3 + AddAlarmList）**
- 缺口：HT160 無 outbound S5F1、alarm catalog 空、S5F3/S5F4 未實作。
- 為何重要：期待 S5F1 alarm 物件(ALID/ALCD/text/source) 的 host 在 HT160 只拿到數字 SVID。
- HT160 現況：`AddAlarmList` 空（`uHGemHT160.cpp:232`）；alarm 僅 SVID 66010/66011；S5F4 為 base stub（`uHGemClass.cpp:176`）、S5F6 回空 list。
- 建議動作：建 alarm catalog（`AddAlarmList`，鍵到 HT160 alarm/Note codes）；加 S5F1 6-element body(timestamp/ALCD/ALID/text/source/extra) 與 alarm CEID 併送；接 inbound S5F3 enable + S5F4 ack。

**P1-6　Real-machine 完成 IO 接線**
- 缺口：HT160 Auto car-taken(`SnAutoX_InputEnd`) 未接線，real Finish 卡在 Ready（sim 自完成）。
- 為何重要：上機前不可信任 real-machine Finish。
- HT160 現況：predicate 有 SOFT_SIMULATE 自完成；real IO 待 HW（memory 'real car-taken IO + device counts pending HW'）。
- 建議動作：對應實際 KYEC car-taken IO 與 infeed `Input(e)nd` sensor、正確極性(ON=有盤)後再上機驗證。

### P2 — 視規格決定

**P2-1　EC 寫入面擴充 + S125 自訂 EC**
- 缺口：HT160 settable ECID 限 2758-2763、S2F15 check/update 停用、無 S125。
- HT160 現況：`uHGemHT160.cpp:303-315`（S2F15 disabled-log）；S125 未 dispatch→S9F3；S125F2/F4 為 stub（`uHGemClass.cpp:229-230`）。
- 建議動作：若 KYEC 需廣 EC config，擴 S2F16 settable ECID map、重啟 S2F15 segment-keyed reload；加 case 125 接 S125F1/F3 與 stub。

**P2-2　Date-time / Loopback（S2F18/F26/F32）**
- 缺口：HT160 路由但 target 為 stub。
- HT160 現況：`uHGemClass.cpp:85-87` 路由 S2F17/F25/F31→base SendUnsupported。
- 建議動作：若 host clock-sync/loopback diagnostics 必要則 override。

**P2-3　SVID 覆蓋（HT9045 common-band）**
- 缺口：HT160 與 HT9045-tuned host 的 SVID 重疊僅 1001/1003/1021/1027 + 38202-38236；HT9045 state 在 1006/1007/1011/1517/1518/1513 + 1010-1190，HT160 在 66xxx。
- 建議動作：或在 HT160 暴露 HT9045 RPTID-502 SVID（尤其 ASCII run-state 1011），或要求 host 學 HT160 66xxx 段。

**P2-4　Loader load-plan（cover-tray + NULL_IC）**
- 缺口：HT160 只存 `TrayCount[0]`，無 cover-tray total/NULL_IC/UI 計數。
- 建議動作：若 KYEC 需 load/cover/IC breakdown，移植 `iAMRCoverTray`(1/2/3 from `TrayForm.iTrayOrder[]`) 算術與 `asendic_Loader.cpp:808` NULL_IC gate。

**P2-5　Color 材料辨識 + CEID 275 + DeviceCount payload**
- 缺口：HT160 無 color 偵測、無 ASE TrayID 讀、無 275 emit；DeviceCount 恆 0。
- 建議動作：僅在 KYEC 規格要求 per-tray ID 上傳或 color-tray 驗證時新增。

**P2-6　其餘 operator/feature RCMD**
- 缺口：HT160 缺 STOP/RESET/HALT、ONE_CYCLE、START_LOT、START_AQL、INITIAL_START(_ART/_MRT)、SWITCH_TO_FT/RT、ENERGY_SAVING、CLEAN_AUTO_SORT_COUNT、PP_MUSIC/PP_SIGNALTOWER/PP_SELECT/PP_PASSWORD、AUTO_CLEAN、AUTOSITEMAP、TRAY_FEED、CONTINUE_RETEST_*/AUTO_RETEST、AUTHORITY_CHECK，及 KYEC-only YIELD_FAIL(CC_KYEC_LEE)。
- 建議動作：依 KYEC 實際 host 命令集擇要移植。優先補 operator-recovery 動詞 STOP/RESET/HALT（HT160 目前只有 PAUSE）。

**P2-7　ONLINE_* 真實化**
- 缺口：HT160 ONLINE_REMOTE/ONLINE_LOCAL 為 mirror-only（只設 `iControlState`）。
- 建議動作：若 host 靠 RCMD 驅動控制狀態，讓其協商真實 HSMS control state（與 P0-2 連動）。
