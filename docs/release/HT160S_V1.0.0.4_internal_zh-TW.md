## 本版主體（客戶要求項）

**清機（Clean Out）排空未完成前不得補料 — 防呆**
客戶 2026-09-16 提出，要求 9/18 前交機。對應 commit `3b8010b`。

### 問題現象

清機排空尚未完成時，若操作員往 Loader 供料車放新料盤，清機流程會永遠停在未完成，而機台**繼續正常生產**。畫面上沒有任何提示，只在 EventLog 留下一行 `CLEANOUT un-retire: LoaderN resumed the ladder`。

機台**不會卡住、不會撞機、不會掉料**——它只是把清機無聲地無限延後。這正是 2026-09-07 掉料事故序列裡「讓生產重新跑起來」的那一步。

### 根因

| # | 位置 | 問題 | 1.0.0.3 |
|---|---|---|---|
| A | `aLoader.cpp:793` `TLoaderModule::IsSupplyCarDry()` | 供料車是否乾是清機退場條件之一。排空途中補料讓它轉為 false，該側重回生產階梯（`aLoader.cpp:1609` 只寫 EventLog，畫面無提示）。**必要條件** | 無守衛 |
| B | `aLoader.cpp:1033` `TLoaderModule::IsAllCleanOutFinish()` | A 成立時完成條件永不成立，`csystem.cpp:2069` 因此永遠不放行 `CheckCleanOutFinish`，CEID 42 不發、六台 Auto 車仍在生產模式。**與 A 合起來充分** | 無守衛 |

### 本版行為

判定採「**由無到有的變化**」而非單純看有無料：

```
清機期間持續觀察 SnLoader_Inputend
  讀到 OFF                → latch「本次排空期間車真的乾過」
  乾過之後又讀到 ON，
  且連續維持 ≥ 1500 ms    → MES0927 停機
離開清機模式              → 兩個旗標清除，等下一次排空
```

- **按下清機時車上原本還有料是合法的**，不會誤報——這是 2026-07-01 已確認的語意（先把車喂乾，再清管線），純準位判定會在按下的瞬間就停機。
- **1500 ms 連續確認是必要的**：前分盤上升會讓光束瞬變。常數與理由與 `aEmpty.cpp` 的 `EMPTY_PHANTOM_TRAY_CONFIRM_MS` 相同。
- **沒有 one-shot latch**：警報就是強制手段。按 RETRY 但沒把盤拿走 → 光束仍亮 → 下一個確認窗又跳。把盤拿走 → 光束滅 → 重新 latch、自動安靜。

### 生效條件（六道閘，`aLoader.cpp:1481-1484`）

```cpp
if(LoaderNo==1 && GeneralSetting.bCleanOutRefillGuard &&
   GeneralSetting.bUseAMR==false &&
   IsSoftSimulate()==false && HSys.LastSet.iRealDummy!=DUMMY &&
   HSys.Sen.SnLoader_Inputend.Enable==true)
```

| 閘 | 理由 |
|---|---|
| `LoaderNo==1` | `DoLoader` 每個 cycle 對同一物件呼叫兩次，兩次都評估會雙重警報 |
| `bCleanOutRefillGuard` | `[Safety] CleanOutRefillGuard`，預設 **true**，即時讀取不需重開程式 |
| `bUseAMR==false` | 用 AMR 時補料是 AGV 的工作，不是操作員違規。讀 `[HardwareInstall] UseAMR` |
| `IsSoftSimulate()==false` | 模擬無實體 IO |
| `iRealDummy!=DUMMY` | DUMMY 乾跑不報 |
| `SnLoader_Inputend.Enable` | 未安裝的點永不擋料 |
