# ALID Option D — 已裁定規格（20260902）

本文件是 HT160S S5 ALID 重新編碼的**唯一權威規格**。所有實作、文件、模擬器、給客戶的說明
都以此為準。使用者於 2026-09-02 逐項裁定。

背景：京元 (KYEC) 要求傳送的 alarm code 最多 9 碼（ALID ≤ 999,999,999）。
先前的雜湊方案最大 3,184,282,107（10 碼）；照抄 HT9046LS `%d%02d%06d` 的方案（Option E）
因與客戶自己的 9046LS 目錄**撞號 47 筆**而被否決。

## 1. 編碼規則

    ALID = Class * 100,000,000 + Payload          // 恆為 9 碼

| Class | 條件 | Payload | 範例 |
|---|---|---|---|
| 0 | **永不產生**（會少於 9 碼） | — | — |
| 1 | 碼字串以 `JAM` 開頭 | 三字母後的數字尾 | `JAM0913` → `100000913` |
| 2 | 碼字串以 `WAR` 開頭 | 同上 | `WAR0963` → `200000963`、`WAR16120` → `200016120` |
| 3 | 碼字串以 `MES` 開頭 | 同上 | `MES1421` → `300001421`、`MES0920` → `300000920` |
| 4 | 恰 5 字元純數字，首字 `4`（汽缸） | **整個 5 碼碼值** | `40000` → `400040000` |
| 5 | 恰 5 字元純數字，首字 `5`（馬達） | 同上 | `50000` → `500050000` |
| 6 | 恰 5 字元純數字，首字 `6`（吸嘴） | 同上 | `60000` → `600060000` |
| **7** | 恰 5 字元純數字，首字 `7`（`eRecordProcess`） | 同上 | `70000` → `700070000` |
| **8** | 恰 5 字元純數字，首字 `8`（`eOther`） | 同上 | `80000` → `800080000` |
| 9 | 以上皆非（未登錄的自由字串） | 舊 31 進位雜湊折成 8 碼 | `SnFKCleanOut` → `991410149` |

**Class 9 的語意** = 「此 ALID **不在** S5F6/S5F8 警報目錄內，請從 ALTX 的第一個 token 讀警報碼」。

**Host 解碼**

    class   = ALID / 100000000
    payload = ALID % 100000000
    class 1/2/3 -> 前綴字母 + payload（依修正 1b 補零至 4 或 5 位）
    class 4..8  -> payload 補零至恰 5 位
    class 9     -> 不在目錄

## 2. 強制修正（全部已裁定）

### 修正 1 — 互斥性守衛（class 1/2/3 payload 上限 999,999）
class 1/2/3 的 payload **超過 999,999 即降為 class 9**。
（class 4-8 的 99,999,999 上限無所謂，其碼格式恰 5 位、硬上限 89,999。）

**理由（實測）**：9046LS 全部 2,738 筆 ALID 中，**第 2-3 位為 `"00"` 的筆數 = 0**
（payload 最小值 1,000,101，UnitNo 恆 ≥ 1）。Option D 的 class 1/2/3 因本修正而
payload < 1,000,000，故第 2-3 位**恆為 `00`** → 兩集合在共用首位數字下仍於第 2-3 位分離。
若不設此守衛，`MES14001421` 會算出 `314001421`，正好撞上 9046LS 自己的 `MES1421`。
**今日成本 = 零**（在役最長尾數 `WAR16121` = 16,121）。

### 修正 1b — 尾數規範化（消除前導零非唯一性）★ 20260902 新增裁定
class 1/2/3 的數字尾**必須**滿足：

    len(tail) == 4  且  value <  10000      （標準形，例 "0913"、"1421"）
    len(tail) == 5  且  value >= 10000      （例 "16120"）

不符者降為 class 9。

**理由**：`payload = int(tail)` 會吃掉前導零，導致 `MES1421` / `MES01421` / `MES001421`
全部算出 `300001421` — 三個不同字串同一個 ALID。本修正把每個 payload 值鎖定到唯一的字串形式。

**⚠ 不可用「拒絕前導零」這個直覺做法** — 會打死 11 支在役碼
（`JAM0913`、`MES0920`、`MES0924`、`MES0925`、`WAR0154`、`WAR0330`、`WAR0462`、`WAR0475`、
`WAR0962`、`WAR0963`、`WAR0970`，全部是 unit 01-09 的 4 位尾數 `0UNN`）。

**驗證（20260902 實測 `system\AlarmList.csv`）**：65 支前綴碼中
尾數長度分布 `{4: 63, 5: 2}`，長度 ≥ 5 且首位為 `0` 者 **0 支**，
本規則淘汰的在役碼 **0 支** — 全 65 支存活。

**⚠ 已知後果（需在規格書與內部命名規範中寫明）**
- **unit 01-09 每個 unit 上限 100 支警報**（尾數 `0UNN`）；5 位尾數 `0UNNN` 為非法。
- unit 10-99 可用 `UUNN`（100 支）或 `UUNNN`（1000 支）。
- 因此未來若 unit 09 需要超過 100 支警報，**必須改用 unit ≥ 10 的編號**，
  不可寫成 `WAR09120`（該字串在本規則下非法，會降為 class 9）。

### 修正 2 — 啟動自檢
`SYSTEM_MODULAR::CreateSystemAlarmCode()`（`database.cpp`，自 `:810`）結尾，
對 `mapAlarmCodeList` 每一列檢查 `ComputeAlarmAlid(code)`：
1. 必須恰 9 碼
2. 必須**不是** class 9
3. 必須在全表唯一

違反者**大聲回報但不阻擋開機**。回報通道：`g_EventLog.Log()` — 每筆違規一行 + 一行總結，
寫入每日 EventLog CSV，隨 State Record zip 打包（本專案既有的事後分析載體）。
不得使用 `ShowMyMessage`（會停機）或 modal（記憶 `modal-subform-zorder-hang-fix`）。

**註**：`database.cpp:1077-1101` 已有一個 20260626 加入的警報碼碰撞守衛（只檢查 4/5/6 開頭的
純數字 key 是否符合 `<fam><3-index><1-err>` 結構形），修正 2 應與它併存或整合，不要重複實作。
⚠ 該既有守衛的註解自述 **"Observe-only (OutputDebugString)"** — 也就是**在現場機台上完全看不到**
（沒有 debugger 就沒有輸出）。這正是修正 2 必須改走 `g_EventLog.Log()`（`cEventLog.h:27`，
已被 `aAuto1To6.cpp:1327`、`aLoader.cpp:106` 等處使用）的理由。

## 3. 實測性質（Option D + 全部修正）

| 項目 | 值 |
|---|---|
| 宇宙 | 532（485 註冊 + 47 自由字串） |
| 碰撞 | **0** |
| 9 碼符合 | **532 / 532** |
| 值域 | min `100000913`（`JAM0913`）／ max `999752848` |
| 有號 int32 相容 | **兩端皆在** → 「須以無號 32 位元解析」的警告全部作廢 |
| 變動筆數 | 530 |
| 壓力測試 | 3,371,021 字串 → 3,364,519 distinct，**全部恰 9 碼，零筆落入 9046LS 集合**；碰撞只在 class 9（1,186 筆），class 1-8 零碰撞 |
| 與 9046LS 交集 | **0（空集合）** |

**互斥性分離原理**
- class 4-8（`[4e8, 9e8)`）與 class 9（`[9e8, 1e9)`）→ **靠首位數字**分離
  （9046LS 首位只有 `{1,2,3}`，實測 2,738 筆零例外）
- class 1/2/3 共用首位 → **靠第 2-3 位**分離（見修正 1）

**9046LS 基準（實測，非假設）**：`D:\HT9045\Error\AlarmCodeList.txt` 2,738 筆，
自第一原理重算並與客戶自己的 `D:\HT9045\SECS\SECS\SYSTEM\AlarmData.def` 第 8 欄
交叉比對 **零不符**；2,737 筆恰 9 碼（唯一例外 `"41"` unknown 列 = `000000000`），
min `101,000,109`、max `330,003,021`，UnitNo 範圍 **1..31**（唯一例外是 `41` unknown 列，
UnitNo=0 → ALID `000000000`=0，不在 9 碼集合內），9 碼集合中 payload < 1,000,000 者 **0 筆**。
（20260902 複驗：自 `AlarmCodeList.txt` 重算 2,738 筆，與 `AlarmData.def` 第 8 欄 2,738 個值比對，
重算有而 def 無 = 0；def 有而重算無 = 1 = 該 `41` 列。）
