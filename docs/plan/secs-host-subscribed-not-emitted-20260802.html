三、B 可補，且我方零阻塞（2 個）

CEID 48 — Change EC（設定值被修改）

  • 現況：無發射點，但我們已經在處理 S2F15 的 EC 寫入 （uHGemHT160.cpp:1120 的 ECID>=2758 && ECID<=2763 閘）。
  • 補法：S2F15 寫入成功後發 CEID 48。工作量極小。
  • 價值：host 訂了它，代表在意「誰改了機台參數」——可稽核性，MES 常見需求。

CEID 78 — Jam Skip IC Count（卡料／跳過顆數）

  • 現況：無發射點，但兩個資料源本週剛好都到位—— tRunData.JamCount（本週建立的 jam 機制）與 tRunData.iAutoSkipCount（既有）。
  • 價值：接上操作員筆記第 6 條「jam rate」的同一條資料鏈，host 端也能收到。

四、C 語意需確認（1 個）

CEID 70 — Barcode Reader Enter

  • 9045 06-08 發了 13 次——當天第 6 高頻事件，顯然是實際在用的功能。
  • 語意不確定：可能是「操作員進入條碼輸入頁面」，也可能是「讀取器讀到資料」。
  • HT-160S 有 Top/Color CCD 的 2D 讀取，也有 uQwertyKey 條碼輸入介面， 兩種語意都可能對應——補錯邊等於送假資料。
  • 動作：查 9045 觸發點確認語意後再決定。我方可自查，不必問京元。

六、E host 自己關掉（1 個）

CEID 80 Read Now Handler Data：07-31 15:02:57.752 host 送 S2F37 <L[2] <Boolean 0x00> <L[1] <U4 80>>> = 明確 disable。 它先在 14:57:41 關閉全部、15:02:56 重新開啟全部、然後只挑 80 關掉。 這是 host 刻意不要的。

七、要請京元改的兩件事

  1. RPTID 524 綁錯事件——建議改綁到已在 CEID 272 上的 RPTID 2001， 否則 Auto4-6 盤數永遠收不到。
  2. 我們已經在發、他們卻沒訂的 16 個事件——含 Lot End(8)、Pause(2)、Auto 卸盤(136-138/145-147)、UPH 記錄(53)、Load Tray Finish(66)。 我方零工作量，他們在 provisioning 加幾行綁定就收得到。

八、9045 素材的其他發現

8.1　CEID 27 佔 9045 全日事件的 63%
9045 06-08 共發 645 則、46 種，其中 CEID 27 Change Machine State 就發了 406 則。 這證實了我們本週補 SVID 1011 Machine State 的優先順序是對的—— 它是 host 端資訊量最大的單一欄位。

8.2　EventReport_ReportID.def 全檔只有一列（1 → 1027）。 這印證了先前判定：9045 的 AddReprot() 是個 no-op bug（迴圈跑 275 次但永遠寫死 RPTID 1）， 所以 9045 出廠時除 CEID 1 外每個事件都送空 L,0。我們沒有照抄那個 bug 是對的。

8.3　9045 會發、我方無發射點的 16 個（超出本文那 20 個的範圍）： 23, 26, 34, 44, 49, 50, 55, 58, 59, 60, 63, 67, 70, 212, 213, 250。 其中只有兩個對分選機有意義：

  • CEID 49 Tray Feed Finish：我們有 Tray Feed 功能，但 CheckAllTrayFeedFinish() 是回傳 false 的 stub （csystem.cpp:1955-1961），所以永遠發不出來。既有已知缺口。
  • CEID 23 Enter Debug Page：我們有維護頁面，可對應。低價值。

其餘 13 個全是 ART／FT／contact-height 等測試機流程。
